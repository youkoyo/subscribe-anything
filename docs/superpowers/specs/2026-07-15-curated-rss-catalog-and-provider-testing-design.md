# 预置 RSS 源目录管理与供应商测试设计

## 目标

为管理员在“配置”中提供独立的“预置 RSS 源”页面，用于管理产业信息源偏好所使用的具体 RSS 目录条目。同时为 AI 供应商与搜索供应商增加安全的 API 可用性测试。

## 范围

### 预置 RSS 源

- 在管理员“配置”页新增“预置 RSS 源”标签。
- 列出目录中的具体源，展示名称、RSS 地址、分类、信息源偏好、可信度和更新时间。
- 支持按名称/地址搜索，按分类和偏好筛选。
- 支持新增、编辑与删除。编辑可修改 RSS 地址、分类、偏好、可信度、名称与关键词。
- 不增加启用/停用开关；删除仅移除目录条目，不触及已建立的信息池、订阅和历史采集数据。

### API 测试

- AI 供应商每个配置均可触发测试，使用该供应商的 base URL、API key 和模型进行最小请求。
- 搜索供应商可对当前编辑中的 Tavily 或 Serper 配置执行最小测试查询。
- 测试按钮可在保存前使用；服务端仅接收当前表单值，不存储测试过程中的密钥。
- 只返回成功、失败原因类别与耗时；不返回或记录 API key、Authorization 头或上游完整响应。

## 架构

复用现有 `discovery_source_catalog` 数据表和预置源匹配模型，为管理员增加目录 CRUD API。预置 seed 只是空库的初始值；管理员新增、编辑和删除后，后续发现流程直接使用数据库中的目录。
为 AI 和搜索供应商分别增加受管理员权限保护的测试 API。测试服务设置严格的超时和最小响应读取，将该次配置作为短暂请求输入使用。

## 校验与错误处理

- RSS 地址必须是 `http` 或 `https` URL，同一 `feed_url` 不得重复。
- 分类、偏好、可信度仅允许已定义的枚举值；名称与地址为必填。
- 删除前显示不影响已建信息池的确认提示。
- 测试失败按“配置缺失”、“认证失败”、“超时/网络”、“上游服务拒绝”归类展示，不会泄露密钥。

## 验证

1. 管理员可在新标签中查看、搜索、筛选和管理预置 RSS 源。
2. 新增和编辑会验证地址与枚举值；重复地址被拒绝。
3. 删除一条目录源不改变已建产业信息池。
4. 两类供应商的测试均有成功、认证失败和超时的稳定反馈，且响应不含密钥。

## 非目标

不重新导入 OPML，不增加启用/停用开关，不在测试时更新或注销已存储的供应商配置。
