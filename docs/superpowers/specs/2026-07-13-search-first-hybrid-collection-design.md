# 搜索优先的混合采集架构设计

## 目标

让产业监测能够稳定发现并推送用户条件对应的近期新闻，尤其是主流媒体和地方事实源中的突发事件；不再把“网站存在相关文章”等同于“网站首页或搜索页可生成稳定采集脚本”。

默认新闻时间窗口为 14 天。发布时间必须来自原文、结构化数据或搜索提供商的明确日期，禁止用入库时间代替发布时间。

## 核心策略

同一条产品流程内部使用两类采集器：

1. `search` 搜索采集器：按监测画像定时执行短查询，直接发现文章 URL，适合主流媒体、地方媒体、政府新闻和突发事件。
2. `feed` 稳定源采集器：定时拉取已验证的 RSS、Atom、JSON API 或静态列表，适合协会、政府公告和行业垂直媒体。

两类采集器共享同一个文章验证、时间过滤、用户条件匹配、去重和信息池写入流程。用户界面仍然是一条构建链路，不暴露为两个独立产品通道。

## 监测画像与查询计划

用户条件先被结构化为：

- 产业同义词；
- 事件与风险词；
- 经营与政策词；
- 企业、品牌和机构；
- 地区；
- 时间窗口；
- 排除项。

系统根据画像生成多个短查询，禁止把完整条件串直接拼成单条搜索语句。查询包含：

- 产业词 + 事件词；
- 产业词 + 企业/品牌；
- 产业词 + 地区；
- 产业词 + 政策/经营词；
- 权威来源的 `site:` 定向查询；
- 不限域名的开放查询。

查询计划持久化，可在后续采集中重复执行。用户条件差异足以改变检索意图时创建或扩展监测画像，不得无条件复用陈旧的默认产业池。

## 管理员来源偏好

管理员配置只影响检索优先级和权威性评分，不作为硬白名单，也不强迫系统为网站首页生成脚本。

默认全国性必查来源包括新华网、人民网、中国新闻网和央视新闻；其他全国媒体可设为“优先”或“补充”。地方来源不作为全局默认，由管理员根据具体业务添加。

每个配置包含名称、域名、来源类别、优先级和启用状态。搜索采集器优先执行“必查”站点查询，再执行开放检索。

## 搜索结果验证

搜索结果只是候选文章。进入信息池前必须完成：

1. 规范化并验证文章 URL；
2. 提取标题、摘要、发布者和发布时间；
3. 验证发布时间在用户窗口内；
4. 验证标题、摘要或正文匹配监测画像；
5. 排除首页、栏目页、商品页、关于我们和旧专题页；
6. 按 canonical URL、内容指纹和相似标题去重；
7. 为权威性、相关性、时效性和证据完整度评分。

优先抓取原文。若权威媒体因反爬无法读取，但搜索结果提供明确标题、摘要、发布者和日期，可作为“搜索证据”入池，并标记较低证据等级；缺少真实发布日期时拒绝。

## 稳定源准入

只有以下来源进入脚本/稳定源阶段：

- 已验证可解析的 RSS/Atom；
- 已验证返回数据的 JSON API；
- 服务器现场抓取并解析出至少一条近期匹配文章的静态列表页。

网站首页、动态站内搜索页、商品目录、历史专题页和没有近期匹配样本的页面不得进入脚本生成。

RSS/Atom 和常见 JSON 优先使用内置解析器。只有在真实页面结构和链接已被捕获、且内置解析器不适用时，才调用 LLM 生成脚本。LLM 每次提交完整 `async function collect()`，最多验证三次。

## 发现源页面

发现阶段改为展示“采集方案”，包括：

- 结构化监测画像；
- 将执行的短查询；
- 必查和优先域名；
- 搜到的近期样例文章及其发布日期、匹配原因和证据等级；
- 已验证的稳定 RSS/API/列表源；
- 每个候选的采集方式：`search` 或 `feed`；
- 排除候选及原因。

管理员可以启用或停用查询、来源和稳定采集器。原始 LLM 调用日志继续保留，但不作为主要决策界面。

## 生成脚本页面

`search` 类型显示“检索方案验证通过”，不生成 JavaScript。

`feed` 类型按以下顺序处理：

1. 内置 RSS/Atom 解析；
2. 内置 JSON 解析；
3. 已确认结构的静态列表脚本；
4. LLM 脚本作为最后手段。

生成成功的标准不是“脚本能返回数据”，而是现场样本至少包含一条时间窗口内且匹配监测画像的文章。

## 运行、去重与推送

调度器分别运行搜索采集器和稳定源采集器，再统一调用文章验证管线。每条记录保留：采集方式、查询或来源 ID、证据等级、原始发布日期、相关性分数和权威性分数。

普通用户条件参与信息池匹配。日报只选择窗口内、未发送且符合用户条件的文章。没有匹配内容时仍发送空日报，正文提示“目前没有匹配用户条件的新闻资讯，请修改条件或联系管理员”。

## 失败与降级

- 单个查询失败不阻塞其他查询；记录提供商错误并按退避策略重试。
- 单个稳定源失败不阻塞搜索采集器。
- 原文不可抓取时仅在搜索证据完整时降级入池。
- LLM 额度不足只影响需要 LLM 的特殊列表源，不影响搜索采集、RSS 和 JSON 内置采集。
- 构建成功允许部分采集器可用，但至少要有一个经过验证的搜索计划或稳定源。

## 数据迁移与兼容

现有脚本来源保持可运行。新增采集器类型和检索计划字段后，旧来源默认标记为 `feed_script`。新建产业构建使用新流程；旧构建可由管理员重新验证并迁移，不自动信任历史成功样本。

## 验收标准

以“国内鞋业相关新闻、默认 14 天”为例：

- 查询计划包含鞋厂事故、鞋业经营、地区和权威媒体定向查询；
- 能发现并保留近期权威媒体的鞋厂火灾文章，即使媒体首页不可生成脚本；
- 2023、2025 年文章、商品页和关于我们页面不能作为当前来源证据；
- 人民网社会 RSS 若近 14 天没有鞋业内容，应作为不适用稳定源排除，但不影响搜索采集器发现人民网其他频道文章；
- 动态搜索页不进入 LLM 脚本生成；
- 最终信息池和日报只包含发布日期真实、时间合格且满足用户条件的新闻。
