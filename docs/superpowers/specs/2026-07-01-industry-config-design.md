# 产业配置与订阅创建关联设计

日期：2026-07-01

## 背景

当前系统已经具备通用订阅能力：用户输入订阅主题和监控条件，AI 发现数据源、生成采集脚本、定时采集消息卡片并生成分析报告。产业情报智能体方案要求进一步支持“按产业配置监控”，让用户能够先维护产业信息，再在新增订阅时选择对应产业配置。

本设计将“产业配置”定义为新增订阅的业务模板，而不是孤立的字典页面。产业配置承载产业名称、关键词、地区、风险事件词、推荐数据源类型等信息，用于降低新增订阅时的填写成本，并为后续 AI 找源、脚本生成和产业情报分析提供上下文。

## 目标

第一版目标：

- 新增一级菜单“产业配置”。
- 支持用户维护产业配置。
- 新增订阅时可选择一个产业配置。
- 选择产业配置后，自动填充订阅主题和监控条件。
- 订阅保存时记录关联的产业配置，并保存创建时的配置快照。

用户价值：

- 业务人员可以把“化工原料产业”“煤炭产业”“食品加工产业”等监控画像预先配置好。
- 新建产业订阅时不需要反复手写关键词和风险关注点。
- 后续订阅、采集、报告都能追溯其来源产业配置。

## 非目标

第一版不直接实现以下能力：

- 不做产业事件中心、事件归并和事件时间轴的完整数据模型。
- 不做产业风险因子生成、因子验证和策略联动。
- 不接入第三方舆情 API 的真实配置管理。
- 不改变采集脚本沙箱的返回契约。
- 不把产业配置强制应用到所有订阅；普通订阅仍可不选产业配置。

这些能力作为后续阶段接入。

## 信息架构

新增导航入口：

- 桌面侧边栏：在“订阅”和“收藏”之间增加“产业配置”。
- 移动底部导航：增加“产业”入口，整体为“订阅 / 产业 / 收藏 / 配置”。

新增页面路径：

- `GET /industries`

页面主结构：

- 顶部标题区：页面名“产业配置”、说明文字、创建按钮。
- 配置列表：展示产业配置卡片或表格。
- 新建/编辑弹窗或抽屉：维护单个产业配置。

## 产业配置字段

每个产业配置包含：

- `name`：产业配置名称，例如“化工原料产业”。
- `category`：产业大类，例如“化工产业”。
- `subCategory`：细分产业，例如“化工原料”。
- `description`：产业说明。
- `keywords`：产业关键词，如“危化品、化工园区、化工原料”。
- `riskTerms`：风险事件词，如“爆炸、泄漏、环保处罚、停产整顿”。
- `regions`：重点地区，如“山东、江苏、浙江、重点化工园区”。
- `entities`：重点企业、园区或上下游对象。
- `sourceTypes`：推荐数据源类型，例如“权威事实源、新闻发现源、社媒线索源、公众号源”。
- `alertLevel`：默认关注等级，例如“一般关注、重点关注、需跟踪、需预警”。
- `isEnabled`：是否启用。

第一版字段以文本和标签输入为主，避免过早建设复杂字典体系。

## 新增订阅流程

在现有 `Step1Topic` 中增加一个可选字段：

- `产业配置`：下拉选择，默认“不使用产业配置”。

交互规则：

- 未选择产业配置：保持现有普通订阅流程不变。
- 选择产业配置后：
  - 订阅主题自动填充为“{产业名称}动态监测”。
  - 监控条件自动填充为产业关键词、风险事件词和重点地区的组合文本。
  - 用户仍可手动编辑主题和监控条件。
  - 页面展示一块“已应用产业配置”的摘要，列出关键词、风险词和重点地区。

保存规则：

- 创建订阅时保存 `industryConfigId`。
- 同时保存一份 `industryConfigSnapshot`，记录创建订阅时使用的产业配置内容。
- 之后产业配置被修改，不自动改变已创建订阅的监控语义。

## 数据模型

新增表：`industry_configs`

建议字段：

- `id`
- `userId`
- `name`
- `category`
- `subCategory`
- `description`
- `keywordsJson`
- `riskTermsJson`
- `regionsJson`
- `entitiesJson`
- `sourceTypesJson`
- `alertLevel`
- `isEnabled`
- `createdAt`
- `updatedAt`

修改表：`subscriptions`

新增字段：

- `industryConfigId`：可为空，引用 `industry_configs.id`。
- `industryConfigSnapshot`：可为空，JSON 字符串。

快照理由：

- 保留订阅创建时的产业监控画像。
- 避免产业配置后续变更导致旧订阅含义漂移。
- 为后续报告、审计、调试 AI 生成结果提供上下文。

## API 设计

新增接口：

- `GET /api/industry-configs`：获取当前用户的产业配置列表。
- `POST /api/industry-configs`：创建产业配置。
- `PATCH /api/industry-configs/[id]`：更新产业配置。
- `DELETE /api/industry-configs/[id]`：删除产业配置。

订阅创建接口调整：

- `POST /api/subscriptions`
- `POST /api/subscriptions/managed`

新增可选请求字段：

- `industryConfigId`
- `industryConfigSnapshot`

接口校验：

- 只能选择当前用户自己的产业配置。
- 禁用状态的产业配置不出现在新增订阅选择列表中。
- 已被订阅使用的产业配置删除时，不影响已有订阅快照。

## AI 上下文接入

第一版只完成数据保存和订阅创建自动填充。

后续增强时，将产业配置注入智能体：

- `findSourcesAgent`：带入产业关键词、地区和推荐数据源类型，提升找源准确率。
- `generateScriptAgent`：带入产业风险事件词，让采集脚本更偏向产业情报内容。
- `analyzeAgent`：带入产业配置快照，让报告围绕产业、地区、风险线索输出。

注入方式建议使用结构化文本片段，而不是把整个 JSON 原样塞给模型。

## 页面状态与错误处理

产业配置页面：

- 加载中：使用现有 skeleton 样式。
- 空状态：提示“还没有产业配置”，提供“创建产业配置”按钮。
- 保存失败：使用 toast 展示错误。
- 删除确认：使用确认弹窗，提醒已创建订阅不会受影响。

新增订阅页面：

- 产业配置列表加载失败时，仍允许普通订阅创建。
- 选择产业配置后自动填充，但不覆盖用户已经手动修改过的字段，除非用户重新选择并确认覆盖。
- 产业配置被禁用或删除后，不影响已经进入创建流程的订阅，但提交时需要重新校验。

## 测试策略

后端测试：

- 创建、更新、删除产业配置。
- 用户隔离：用户不能读取或使用他人的产业配置。
- 创建订阅时正确保存 `industryConfigId` 和 `industryConfigSnapshot`。
- 不选择产业配置时，现有订阅创建流程保持兼容。

前端测试：

- 菜单入口渲染。
- 产业配置空状态和列表状态。
- 新建/编辑产业配置表单。
- 新增订阅选择产业配置后自动填充主题和条件。
- 用户手动编辑后不会被意外覆盖。

手工验证：

- 创建一个“化工原料产业”配置。
- 新增订阅时选择该配置。
- 确认主题、监控条件自动填充。
- 完成订阅创建后，确认订阅记录保留产业配置关联和快照。

## 分阶段实现

第一阶段：

- 新增数据表和订阅表字段。
- 新增产业配置页面和导航入口。
- 新增产业配置 CRUD API。
- 在新增订阅第一步支持选择产业配置并自动填充。
- 创建订阅时保存关联和快照。

第二阶段：

- 将产业配置上下文注入 `findSourcesAgent`、`generateScriptAgent` 和托管创建流程。
- 在订阅详情和报告生成中展示产业配置摘要。

第三阶段：

- 建设产业事件、事件时间轴、风险线索等级和产业情报看板。
- 将产业配置沉淀为后续风险因子候选的基础数据。

## 设计结论

产业配置页面应作为产业情报智能体的业务模板中心。新增订阅时选择产业配置，是第一版最关键的连接点。这样既能复用当前通用订阅系统，又能自然过渡到产业情报中心和后续风险因子智能体。
