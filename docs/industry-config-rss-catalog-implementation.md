# 产业信息池与预置 RSS 源库：实施说明

## 已落地的执行链路

```text
管理员输入产业名称与自然语言关注方向
  → AI 自动生成产业画像（核心词、关联词、语境排除词）
  → 按管理员选定的信息源偏好匹配预置 RSS 源库
  → 所有匹配且可访问的 RSS 均执行（仅限制并发，不限制来源数量）
  → 画像规则预筛 + AI 逐条判定：强相关 / 有关 / 无关
  → 强相关和有关逐条写入信息池，不跨来源合并事件
  → 若本轮预置源合格内容为 0，才回退旧的 AI 找源与脚本生成流程
```

## 关键实现

- `discovery_source_catalog` 保存 204 条 OPML 来源及偏好、可信度、健康状态；启动迁移后幂等写入。
- 产业配置持久化 `source_preferences_json`、回退开关和 `term_profile_json`。管理员不维护关键词表，画像由 AI 自动生成；模型临时不可用时以原始产业名安全降级。
- 预置 RSS 使用统一脚本解析 RSS/Atom，不为每个来源重复调用脚本生成模型。后续调度也复用该脚本。
- 每个来源的文章分别保存；同一事件被多家来源报道时不会被合并。数据库仍用来源内内容哈希阻止重复采集。
- 预置源只允许 `strong` 与 `related` 标签写入信息池；`irrelevant` 不入池。

## 管理端界面

创建页只把“产业名称”“关注方向”“信息源偏好”放在主流程中；高级资料与投递选项按需展开。右侧摘要实时显示预计执行来源数，并明确说明“全量执行、零结果才回退”。深蓝青色主视觉保持不变，卡片状态与展开动作使用受 `prefers-reduced-motion` 保护的轻量过渡。

## 运行与迁移

新增迁移：`0001_spotty_lorna_dane.sql`（目录及来源追踪字段）与 `0002_groovy_lady_mastermind.sql`（AI 产业画像）。部署时按既有启动流程运行迁移即可；无需重新导入 OPML 文件。

## 验收重点

1. 创建“鞋业”等仅含产业名的配置时，系统生成画像而非要求管理员填写同义词。
2. 选择“权威、主流、财经、行业、趋势”后，预览显示这些偏好下的全部匹配来源；没有“最多 5 个”的来源截断。
3. 预置源有强相关或有关内容时，构建日志不应进入旧找源流程，也不应为每个 RSS 调用脚本生成模型。
4. 预置源本轮没有合格内容时，日志明确显示回退，并继续使用旧找源/脚本流程。
5. 不同来源的同一新闻保留为多条信息池记录。
